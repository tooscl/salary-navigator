# Claude Code: сбор вакансий T&L

Это точка обнаружения навыка, не отдельная реализация парсера.
Найдите корень текущего checkout по `Scraper/extract.js` и прочитайте:

1. [CLAUDE.md](../../../CLAUDE.md) и [AGENTS.md](../../../AGENTS.md).
2. [Общий SKILL.md](../../../Scraper/skills/collect-avito/SKILL.md).
3. [HOSTS.md](../../../Scraper/skills/collect-avito/references/HOSTS.md), раздел Claude Code.
4. [OUTPUT_CONTRACT.md](../../../Scraper/skills/collect-avito/references/OUTPUT_CONTRACT.md):
   обязательный формат результата и публикации, общий с Codex.

Перед каждым запуском после остановки проверьте, создан ли plan.json пакета.
Если плана/очереди/raw ещё нет, снова получите командный main и перечитайте
общий skill из свежего checkout до запуска/возобновления агента. Это подготовка,
даже если участник сказал «продолжить». Существующий план требует resume с
закреплённой версией. Журнал ошибок и бюджет сохраняются в обоих случаях.

Используйте проектных агентов `avito-capture` (`model: haiku`) и
`avito-review` (`model: sonnet`) из `.claude/agents/`. Не используйте Codex
model ID и инструмент `collaboration.spawn_agent` в Claude Code.
Ведущий запускает оба этапа последовательно и ждёт результат каждого;
агенты этапов повторно себя не делегируют. Имена моделей в runner — запись
фактического исполнения, не команда переключения модели.

Для первого запуска следуйте общему `references/FIRST_RUN.md`. Скрипты,
экстрактор и данные остаются в `Scraper/` и `Data/` этого checkout. Скачайте
весь репозиторий: копирование одной `.claude/skills/collect-avito/` недостаточно.
Обычные параметры, фильтры, остановки и публикация определяются общим навыком.

Собирайте техническими пакетами под одним браузерным агентом. Проверяющий
подключается один раз после всего сбора для проверки и публикации; во время
сбора — только при ошибках. Успешный пакет не запускает отдельную проверку.

Если gstack /browse отсутствует, агент сам готовит его по разделу FIRST_RUN.md
«gstack: агент готовит сам до открытия карточек»: официальный Git checkout,
локальная инструкция, setup и проверка. Не заканчивайте запуск одной ссылкой
на ручную установку. До готовности Aside карточки не открываются.

Окружение и preflight --probe-aside проверяет ведущий до запуска агентов:
первый раз готовит и сохраняет настройки, далее повторно использует файлы.
Не делегируйте первичную установку/запрос Happ JSON браузерному агенту.

Ведущий передаёт avito-review базовый remote/ref командного main и требует
сверку новых/повторных ID и изменённых полей. Пустое описание PR, ручной manifest
или не вошедшие в diff исправления не считаются готовой публикацией.
