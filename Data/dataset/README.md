# Общий датасет вакансий

[vacancies.csv](vacancies.csv) — актуальная общая таблица для Analytics и ML.
Одна строка — одна вакансия; ключ — пара `source` + `id`. ID читается как строка.
Одинаковые объявления с разными ID автоматически не склеиваются.

```python
import pandas as pd

df = pd.read_csv("Data/dataset/vacancies.csv", dtype={"id": "string"})
moscow = df[df["city"] == "Москва"]
```

Текущий состав: **12280 вакансий, 115 колонок из 59 выгрузок**.
[Каталог и время сборов](../README.md).
Начальный состав: 238 вакансий, 64 колонки из проверенной выгрузки 21 октября.
Все 55 исходных колонок сохранены, добавлены 9 служебных колонок. У 10 вакансий
сохранён `export_eligibility=fit_review_required`; это отметка для проверки
соответствия срезу, такие строки автоматически не отбрасываются.
Пустота означает отсутствие сохранённых сведений, а не ноль или «нет».
Многозначные поля сохраняются через `; `. Зарплата пока остаётся исходной
строкой `salary_raw`; период оплаты и налоги нельзя предполагать.

## География и характеристики

`city` — город размещения вакансии на сайте, `region` — соответствующий регион.
Если город не виден, явно проверенное исключение хранится в источнике как
`unknown_city_placements` по ID с регионом и точной цитатой видимого расположения;
`city` остаётся пустым. Если весь адрес отсутствует, finalize автоматически
регистрирует `location_missing: true`, пустые `evidence`/`region`,
`region_unknown: true`; строка содержит `city__source=missing`,
`read_status_location=missing` и пустое location_observed/city__evidence. Это
явная запись пропуска, не выдуманная цитата. Без соответствующего исключения
пустой город не проходит проверку.
Место фактической работы из описания их не меняет. `profession` и `segments`
сохраняют категории/срезы отбора; несколько значений не создают дубли строк.
Начиная с collect-avito 1.7.5, `profession` автоматически берётся из выбранных
контролов профессии сохранённой выдачи и проверяется перед сбором/экспортом.
Несколько выбранных профессий разделяются `; `; название вакансии и описание
не используются для заполнения этого поля. Исторические выгрузки не меняются.

При сборе без фильтра профессии `profession` пустая, а `segments` указывает
общую выдачу. Это не классификация вакансии по заголовку; исходный title сохранён.
Для объединения названия колонок приводятся к единой схеме до регистрации:
одна характеристика имеет одно название, разные характеристики не склеиваются.
Сохраняйте все найденные характеристики в отдельных колонках. Новая колонка
появляется во всей таблице, у остальных строк остаётся пустой.

## Наблюдения и обогащение

| Колонка | Значение |
|---|---|
| `source` | Площадка, сейчас `avito` |
| `region` | Регион размещения, заданный явно для городов сбора |
| `first_seen_at`, `last_seen_at` | Первое и последнее наблюдение в зарегистрированных выгрузках |
| `observed_at` | Время наблюдения выбранной версии карточки, равно `last_seen_at` |
| `run_id` | Сбор, из которого выбрана текущая версия |
| `run_ids` | Все сборы, в которых встречался ключ, через `; ` |
| `enrichment_status` | `not_run`, `completed`, `failed` или `unknown` |
| `enriched_fields` | Колонки, заполненные из описания, через `; ` |
| `enrichment_version` | Версия правил/модели обогащения |
| `listing_rank` | Позиция уникальной вакансии в зафиксированной очереди последнего сбора; в исторической выгрузке пусто |
| `military` | True/False: словарное совпадение в названии, не подтверждённая классификация и не фильтр исключения |
| `military_keywords` | Совпавшие термины через `; `; пусто при отсутствии совпадений |
| `military_rule_version` | Версия фиксированного правила, сейчас `military_title_v1` |
| `listing_promoted` | Наблюдённая отметка продвижения в выдаче (`True`/`False`); в исторической выгрузке пусто |

Для исторической выгрузки статус обогащения — `unknown`: единой разметки
происхождения там нет. Это не утверждение, что обогащение выполнялось.
Новые сборы явно ставят `not_run`, если обогащение не запускали. При `completed`
версия обязательна; список полей может быть пустым, если ничего не извлечено.
При `failed` частичные результаты не публикуются как готовое обогащение.

Для каждого обогащённого поля нужны `<поле>__source=description` и
`<поле>__evidence` — точная цитата из сохранённого описания. Эти колонки
добавляются по мере появления обогащения. Явное значение параметра карточки
сохраняйте; при противоречии фиксируйте отдельный признак конфликта и свидетельство.
Статус и цитата обеспечивают проверяемость, но не доказывают правильность вывода.
Географию размещения, ID и другие исходные обязательные поля не обогащайте;
для места работы из текста используйте отдельную характеристику.

## Добавить сбор и обновить GitHub

1. Сохраните новую проверенную неизменяемую выгрузку в
   `Data/avito_runs/<run_id>/exports/vacancies_flat.csv`. Нужны все обязательные
   колонки из `REQUIRED` в [сборщике таблицы](../../utils/build_dataset.py).
   В CSV допускаются только строки с `analysis_status=validated` и
   `export_eligibility=included` или `fit_review_required`.
2. Добавьте запись в [sources.json](sources.json): уникальный `run_id`, `source`,
   путь, SHA-256 исходного CSV и `placement_regions` для каждого города размещения.
   Словарь регионов подтверждается географией сайта, не описанием вакансии.
   Образец — существующая запись. Для новых сборов укажите
   `enrichment_status: "not_run"`; значения в строках имеют приоритет.
3. Выполните из корня:

   ```sh
   python3 utils/build_dataset.py
   python3 utils/build_dataset.py --check
   ```

4. Перед публикацией получите свежий `origin/main`. В отдельной ветке `codex/...`
   от него добавьте только файлы своего сбора, запись
   реестра, общий CSV, manifest и изменения каталога данных. Выполните commit,
   push и откройте PR. Командный процесс сбора включает создание PR с результатом;
   если публикация явно исключена заданием, остановитесь на локальных файлах.
   Доступ к GitHub должен быть настроен; при ошибке сообщите причину и локальный
   результат. По командной договорённости от 27.10.2026 агент после проверок
   сам сливает принятый батч в main и проверяет результат в чистом checkout.
   Обязательные reviews и защиту ветки не обходит. Если права записи нет,
   используется fork участника и PR в общий репозиторий; при праве записи — ветка.
   Длительный сбор публикуется отдельными завершёнными батчами, чтобы принятые
   результаты были сохранены на GitHub до окончания всей работы.

В новые коммиты включаем CSV, raw JSON, проверенные данные, план и паспорт.
DOM/HTML-дампы и скриншоты остаются локальной диагностикой; старые опубликованные
архивы не переписываем. Описание PR формирует `utils/dataset_pr.py` из CSV:
условия сбора, принятые ID, новые/повторные ключи, размерность и новые колонки.
После `git add` утилита также проверяет отсутствие staged браузерных дампов.

Одной выгрузки достаточно. Две и более читаются по тому же реестру. Скрипт
не ищет CSV по каталогам: незавершённые и тестовые сборы не попадают случайно.
Для повторного ключа выбирается целиком самое позднее наблюдение, включая
профессию, сегменты и характеристики; пустые новые значения не заполняются
старыми. Это сохраняет реально наблюдавшуюся версию. Старые значения и срезы
остаются в исходных выгрузках, `run_ids` позволяет найти все наблюдения.
При разных значениях с одним временем скрипт останавливается для проверки.
Удаление объявления не выводится из его отсутствия в новом сборе.

Завершённые исходные CSV не перезаписываются. Общий CSV и manifest — производные
файлы, которые пересобираются целиком. Git хранит их предыдущие версии.
Manifest содержит входные хеши, хеш CSV, колонки и хеш сборщика. Для эксперимента
закрепляйте commit, путь и SHA-256 CSV. Это накопленная выборка наблюдений,
а не гарантия актуальности каждого объявления или полноты рынка.

При параллельных PR обновите ветку относительно `main`, сохраните записи обоих
сборов в реестре и заново запустите сборщик. Конфликты общего CSV/manifest
разрешайте пересборкой. Локальный `--check` проверяет точное соответствие
общей таблицы реестру. [Шаблон GitHub Actions](../../Scraper/templates/dataset-workflow.yml)
готов для установки в `.github/workflows/dataset.yml`; текущему OAuth-токену
не хватает разрешения `workflow`, поэтому CI пока не включён. Установите шаблон
через доступ с этим разрешением; обязательность проверки в защите ветки
настраивается отдельно.

Обычный сбор использует готовый runner collect-avito 1.5. Полный unit suite
выполняется при изменении кода; проверки очереди, карточек, хешей и общей
таблицы выполняются на каждом пакете без участия модели. Новые исправления
фиксируются в automation_changes паспорта и кратко перечисляются в PR.

### Пропуски и город из фильтра

В новых выгрузках `city__source=card` означает разбор расположения карточки,
`search_filter` — заполнение пропуска подтверждённым городом поиска,
`missing` — неизвестный город. `city__evidence` содержит исходное расположение
или ссылку подтверждённой выдачи, `city_anomaly` — причину замены/пропуска.
Полное `location_observed` и raw сохраняются. Для search_filter реестр фиксирует
search_city и search_city_evidence; сборка проверяет их совпадение со строкой.
Пустой регион допустим только с явным region_unknown в зарегистрированном
исключении. Старые выгрузки без маркировки источника не переинтерпретируются.

### Военная тематика: технический словарный сигнал

Правило `utils/title_flags.py` использует только название: БПЛА, ЛНР, ДНР,
СВО, ВАИ, тыл и начала слов донецк…, военн…, тылов…. Регистр не учитывается;
«контракт» сам по себе не срабатывает. Отметка не исключает строку и не требует
чтения описания моделью. Возможны ложные срабатывания по географии Донецка и
пропуски названий без словаря; False означает только отсутствие совпадения.
Это техническая разметка, поэтому enrichment_status остаётся not_run, если
обогащение описания не выполнялось. В общем CSV отметки пересчитываются по
последнему названию и текущей версии правила; manifest содержит версию и хеш
кода. Завершённые исходные выгрузки и их хеши остаются прежними.

### Пропуски при сборе первых N

Отсутствующие отдельные характеристики, описание и расположение сохраняются
пустыми, без повторного обхода, добора или специального вызова Terra.
read_status_description/read_status_location отмечают missing; city_anomaly
объясняет неразобранный город. Остальные наблюдённые поля и raw сохраняются.
full_parameters_read относится только к прочитанному блоку характеристик и
не обещает заполненность всех колонок. ID, заголовок, структура и читаемость
блока параметров проверяются; блокировки/неверный ID/полный отказ чтения остаются
ошибками. Поисковый фильтр не подменяет отсутствующее значение карточки.
