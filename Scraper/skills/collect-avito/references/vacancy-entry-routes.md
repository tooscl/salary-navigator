# Точки входа в вакансии и запасной маршрут

Проверено 28.10.2026 через gstack /browse в собственной Aside-сессии. Это
наблюдённые пути, не гарантии неизменности сайта. Машинный паспорт с заголовками
страниц: [vacancy-entry-routes.json](vacancy-entry-routes.json). Карточки вакансий
для этой проверки не открывались. Чужой активный сбор/вкладки не менялись.

## Названия частей URL

`https://www.avito.ru/moskva/vakansii?context=…`:

- `https://www.avito.ru` — origin сайта.
- `moskva` — региональный сегмент пути (slug города), не профессия.
- `all` в `/all/vakansii` — все регионы России; пишется с двумя `l`.
- `vakansii` — раздел вакансий.
- Сегмент после `vakansii/…`, если он есть, может содержать профессию или
  карточку; непрозрачную кодировку фильтров самостоятельно не конструировать.
- `?context=…` и другие query-параметры берутся из фактической ссылки целиком.
  Их не нужно переносить между городами, дописывать или считать настройкой сети.

Корневой `https://www.avito.ru/vakansii` без региона в TL Demo Test 2 вернул 404.
Он не является проверенной точкой входа и не означает «Все регионы».

## Основной вход

1. Если участник дал точный URL выдачи — используйте его с query-параметрами.
2. Если URL нет, но указан один из городов таблицы, начните с его проверенной
   страницы. Если нужного города нет в паспорте, сначала найдите его через
   географический фильтр внутри вакансий по инструкции ниже. Отсутствие записи
   в таблице само по себе не повод переходить через главную. Для задания без
   географии сначала согласуйте охват; явное «Все регионы» уже задаёт охват и
   не требует выбора города.
3. Подтвердите заголовок, город, нужные фильтры и поиск; затем обычный рецепт
   [vacancy-filters.md](vacancy-filters.md). Нужные контроли смотрите scoped
   snapshot формы: общий snapshot длинной выдачи может обрезаться до формы.
4. Freeze получает фактический конечный URL; таблица не подменяет подтверждение.

## Новый город: сначала фильтр вакансий

1. В собственной вкладке с доступной выдачей вакансий найдите географический
   контроль. На проверке его marker — `search-form/change-location`, текст
   «Москва, район, метро». Возьмите ref из свежего snapshot. Начальный город
   нужен только для доступа к интерфейсу, он не становится географией задания.
2. Откройте «Город или регион», введите заданное название, дождитесь фактической
   подсказки и выберите её. Одного заполнения поля недостаточно. Для одноимённых
   населённых пунктов проверьте регион; при неоднозначности уточните у участника.
3. Примените видимую кнопку «Показать …». Подтвердите фактический URL в разделе
   вакансий, выбранную географию, профессию и остальные условия. Сохраните эти
   свидетельства в плане; только после этого разрешён freeze.
4. Успешный новый маршрут добавьте в таблицу выше и JSON `cities`: название,
   фактический URL, заголовок, дата проверки, путь через фильтр. Если путь содержит
   фильтры профессии/формата, явно сохраните их условия; не объявляйте такую ссылку
   общей городской страницей и не удаляйте параметры для получения выдуманного URL.
   Изменение паспорта включите в тот же PR. Отсутствующая запись не считается ошибкой.
5. Если фильтр не сработал, запишите ошибку и конкретную коррекцию в общий retry.
   Только тогда используйте запасной маршрут, сохраняя запрошенный город. Если
   после запасного входа география также не подтверждена, остановитесь по правилам
   бюджета; не собирайте вакансии начального города вместо заданного.

## Все регионы / без привязки к городу

**Проверено 28.10.2026:** `https://www.avito.ru/all/vakansii` — выдача
по всем регионам России. Точную ссылку с `context` предоставил участник;
на странице также обнаружена ссылка «Вакансии» с href `/all/vakansii`.
Оба входа проверены в собственной вкладке через gstack /browse:

- h1: «Работа и вакансии во всех регионах России»;
- географический контроль `search-form/change-location`: «Во всех регионах».

Для задания «Все регионы» / «по России» / «без привязки к городу» сразу
используйте `/all/vakansii`, либо точную ссылку участника с её query-параметрами.
Не нужно выбирать Москву или вводить «Россия» в подсказках города. Примените
профессию и остальные условия внутри этой выдачи; перед freeze подтвердите,
что общий охват сохранился, нет ограничения городом, районом, метро или радиусом.
Фактический конечный URL и географическое свидетельство сохраните в плане.

`/regions` остаётся справочником городов; корневой `/vakansii` не заменяет
`/all/vakansii`. Предыдущая неудача подсказок географии не означала отсутствия
общей выдачи. В CSV город каждой вакансии берётся из её карточки; `all` и
«Во всех регионах» не являются городом вакансии и не заполняют пропуски города.

## Запасной вход через интерфейс, сохранённый из версии 1.4

Применять только если исходный вход недоступен технически (например, 404),
либо по прямой странице не удалось подтвердить раздел; для города вне таблицы —
после неудачи выбора через фильтр вакансий, а не сразу из-за отсутствия URL.
География задания должна быть подтверждена до выбора региональной главной;
если город/регион неизвестен, сначала уточните его у участника.
Записать ошибку и конкретную коррекцию через общий бюджет retry; не перебирать
вслепую города/домены. CAPTCHA/429/ограничение доступа не разрешают этот переход.

Для Москвы воспроизведено:

1. Собственная вкладка `https://www.avito.ru/moskva` — региональная главная.
   Этот адрес прочитан из breadcrumb «Главная» московской выдачи.
2. Свежий snapshot, видимая категория **«Работа и подработка»**. Ранее могла
   называться «Работа»; ref взять из текущего snapshot. На проверке ссылка
   категории сразу привела в `/moskva/vakansii?context=…`.
3. На проверке конечный h1 — «Работа и вакансии в Москве»; scoped snapshot
   `snapshot(page,{selector:'form',interactive:true})` показал «Профессия»
   и остальные контроли. Если на другом шаблоне сначала открылось «Работа»,
   следуйте только видимой ссылке «Вакансии» и снова подтвердите заголовок.
4. Заново примените все условия задания. Возврат на главную не сохраняет
   подтверждение старых фильтров: проверьте город, профессию/формат, поиск и
   сортировку перед freeze. Зафиксируйте конечный URL и route evidence в плане.
5. После успешной коррекции — stage-ok того же этапа. Не сбрасывайте run_id,
   журнал или общий бюджет. Новые клики выполняются последовательно.

Запасной маршрут через главную проверен сейчас для Москвы; для остальных шести
городов проверены прямые страницы, а не все клики главная→категория.
Успех чтения страницы не доказывает применение фильтров и не является сбором.

**Самара, 06.11.2026:** ввод «Самара» и «Самара, Самарская область» в
геоконтроле показал «Неизвестный город или регион». После записи ошибок и
коррекций по общему retry найденная на `/moskva/vakansii` same-origin ссылка
с видимым текстом «Самара» (`/samara`) открыла главную, где в контроле было
«Самара». По видимой категории «Работа и подработка» открыта выдача вакансий;
затем выбран точный checkbox «Продавец». Подтверждены h1 «Вакансии по
профессии Продавец в Самаре», геоконтроль «Самара, район, метро», checked=true
и пустой поиск. Сохранённый URL содержит профессию и query; это **не** общая
страница Самары и не шаблон для конструирования URL. Смотри точные свидетельства
и маршрут в [vacancy-entry-routes.json](vacancy-entry-routes.json).

**Краснодар, 09.11.2026:** геоконтрол на ввод «Краснодар» вернул
«Неизвестный город или регион». На общей выдаче вакансий Екатеринбурга
наблюдалась ссылка с title и текстом «Краснодар» на `/krasnodar/vakansii`.
После перехода подтверждены заголовок «Работа и вакансии в Краснодаре»,
геоконтрол «Краснодар, район», пустой поиск и отсутствие выбранных профессий.
Ссылка наблюдалась в разделе вакансий; город и фильтры необходимо проверять
снова при каждом новом запуске.
