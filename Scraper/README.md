# Сбор данных через агента

Командный способ сбора — агент, который использует
[collect-avito](skills/collect-avito/SKILL.md), gstack `/browse` и **Aside**.
Сбор идёт техническими пакетами; Terra подключается один раз после всех пакетов
для проверки и публикации, а во время сбора — только при ошибках.
Он работает с видимыми страницами: задаёт фильтры, сохраняет очередь,
читает карточки и готовит выгрузку для анализа.

## Готовый запуск (collect-avito 1.7.21)

Если профессии не указаны, агент предлагает выбрать наши топ-20, весь каталог
без фильтра либо конкретные профессии. Выполненный выбор топ-20 фиксируется
один раз; дополнительных ревизий скрытых контролов и сортировки на каждой
странице нет. Пагинация общая: --limit 5000 задаёт общий объём, --all-pages —
обход доступной выдачи до конца. Если Next пропала или дальше нет новых ID,
фиксируется фактическая очередь, даже если она меньше запроса; это не ошибка. Размер пакета 30 не ограничивает
общий объём. Прерванный freeze возобновляется с сохранённых страниц.

Happ: основной путь на macOS готовит полное подключение из локального кэша.
Если кэш недоступен, запасная routing-ссылка импортирует только правила:
новое подключение не появится. Агент явно объясняет, какой артефакт выдал и
что выбрать после импорта. Процедура — [VPN_HAPP.md](VPN_HAPP.md).

Перед новым сбором агент выполняет `git fetch origin main`, создаёт отдельный
checkout от свежего `origin/main` и читает skill из него до запуска агентов.
Версия, SHA-256 инструкции и commit кода сохраняются в плане. При resume
используется закреплённая версия исходного пакета.

Перед браузерными действиями агент проверяет подключённые профили Aside.
Preflight и runner автоматически выбирают единственный подключённый профиль;
при нескольких используйте TL_ASIDE_PROFILE. Отключённый default-профиль
не означает, что CLI нужно заново устанавливать или авторизовать.

Профессия автоматически переносится из отмеченных фильтров выдачи в план и CSV.
`--profession` необязателен и служит проверкой; расхождение с фильтрами
останавливает freeze/capture/finalize. Без фильтра поле остаётся пустым.

При неоднозначном городе `finalize --city-anomaly-policy blank` оставляет его пустым; `search_filter` использует подтверждённый фильтр поиска. Происхождение и свидетельство сохраняются в `city__source` и `city__evidence`.

[Паспорт точек входа](skills/collect-avito/references/vacancy-entry-routes.md):
городские `/<город>/vakansii` и запасной маршрут через региональную главную
и видимую категорию «Работа и подработка». Корневой `/vakansii` вернул 404.
Новый город сначала выбирается фильтром внутри вакансий; успешный путь добавляется
в паспорт в том же PR. Для «Всех регионов» проверен `/all/vakansii`
с географией «Во всех регионах»; `/regions` — справочник городов.

[Проверенный рецепт фильтров](skills/collect-avito/references/vacancy-filters.md):
страница вакансий → профессия → ссылка города с сохранением профессии.
После технической ошибки — до пяти повторов с конкретной коррекцией; дубли
check-stage не тратят бюджет. Ограничения доступа останавливают сразу.
Новое разрешение человека фиксируется resume-browser со стабильным
authorization-id; журнал не удаляется, а повтор того же authorization-id не пополняет бюджет.
Локальный журнал failures.json общий для всех этапов и агентов run_id.
Новые действия/скрипты закрепляются в skill и том же PR.

Модели Codex: Luna low — браузерный сбор, Terra — проверка и исключения.
Модели Claude Code: avito-capture/Haiku — сбор, avito-review/Sonnet — проверка.
Точки обнаружения и карта файлов — [HOSTS.md](skills/collect-avito/references/HOSTS.md).
Ведущий явно запускает этих агентов; одно упоминание модели в тексте не
переключает текущий чат.

Повторяемый путь теперь реализован в `skills/collect-avito/scripts/run.py`:
`freeze` фиксирует очередь наблюдённой выдачи, `capture` собирает/продолжает
пакет, `finalize` проверяет и регистрирует CSV, `publish` готовит commit/push/PR.
Аргументы и условия отбора — в [skill](skills/collect-avito/SKILL.md).
Исходники скриптов и исторические инструкции не нужно читать на успешном пути.
Preflight встроен в freeze/capture. Полный unit suite нужен при изменении кода,
а обычный сбор проверяется пакетным валидатором и build_dataset --check.

Новый шаблон карточки исправляем в общем коде с тестом и обновлением skill;
файлы и причину регистрируем `run.py note-change` до finalize. Изменения
попадают в паспорт и короткое описание PR вместе с данными. Временные
скрипты не заменяют поддерживаемую реализацию.

Регрессии runner: `python3 -m unittest Scraper.test_aside_runner`.
Проверка экстрактора и настоящего batch-worker в Aside на localhost, без Авито:
`python3 Scraper/test_extract_aside.py`.

## Подготовка рабочего места

Для первого запуска дайте агенту [collect-avito](skills/collect-avito/SKILL.md)
и попросите помочь с настройкой. Он проходит [путь от скачивания до CSV](skills/collect-avito/references/FIRST_RUN.md):
Python 3.10+, gstack `/browse`, Aside с CLI, авторизация и локальные настройки.
Aside предлагает macOS и Windows; полный проход проекта проверен на macOS,
Windows и другие агентные среды ещё требуют проверки. Входы в аккаунты,
системные разрешения и импорт профиля участник подтверждает сам.
Проектный навык доступен по пути `Scraper/skills/collect-avito/SKILL.md`:
достаточно указать его агенту вместе с заданием. Наличие файла в репозитории
не означает, что навык уже установлен в личный каталог каждого участника.

Один раз создайте **локальный**, исключённый из Git файл настроек генератором.
Без VPN:

```sh
python3 Scraper/skills/collect-avito/scripts/setup_workspace.py --mode disabled
```

С Happ:

```sh
python3 Scraper/skills/collect-avito/scripts/setup_workspace.py --mode happ
```

Будут подготовлены JSON-профиль и ссылка для импорта в Happ вне репозитория.
Существующие файлы не перезаписываются. На Windows используйте найденный
`py -3`/`python` вместо `python3`. Генератор не устанавливает программы и не
включает VPN сам: агент помогает выполнить эти шаги по FIRST_RUN.md.

Поддерживаемые настройки:

- Без туннеля: `"tunnel_mode": "disabled"`, `"xray_config_path": null`.
- Happ: `"tunnel_mode": "happ"`, `"happ_routing_path"` — путь к подготовленному
  профилю маршрутизации. Импорт и активация описаны в VPN_HAPP.md.
- С Happ/Xray: `"tunnel_mode": "xray"`, `"xray_config_path"` — абсолютный путь
  к актуальной полной JSON-конфигурации **вне репозитория**.
  Можно использовать `~/…`. Полный конфиг содержит секреты и остаётся локально.
  Другой VPN-клиент требует отдельной проверки маршрута: не называйте его Xray.

Для Happ нужны прямые правила `avito.ru` и `avito.st`, включая поддомены.
Как настроить и проверить их применение — в [VPN_HAPP.md](VPN_HAPP.md).
Скрипт читает выбранный файл и выводит только результат проверки правил.
Сам туннель, профиль и сетевые настройки он не меняет.

## Отдельная диагностика рабочего места

```sh
python3 Scraper/skills/collect-avito/scripts/preflight.py --probe-aside
```

Проверка повторяется целиком: Python, файлы проекта, наличие `/browse`,
Aside CLI и доступность REPL, локальные настройки и правила Xray, если он выбран.
Открывать сайт или менять вкладки для этой проверки не требуется.
Без `--probe-aside` проверяются только локальные зависимости и конфигурация.
Для машиночитаемого результата добавьте `--json`; для другого локального файла —
`--config /абсолютный/путь.json`.

При недоступном Python/файлах проекта/Aside скрипт выводит `NEEDS_SETUP`
и код возврата 2. Отсутствующий или непроверенный конфиг маршрута даёт
`READY_WITH_WARNINGS` и код 0: это не отказ браузера. Агент продолжает первой
обычной загрузкой сайта и не просит заново полный конфиг. Без независимого
измерения маршрута сохраняется `live_route_verified=false`.
Для отдельного статического аудита сети добавьте `--strict-routing`:
тогда проблема конфигурации снова является блокирующей. Общий локальный файл
для разных checkout можно указать через `--config` или `TL_AVITO_CONFIG`.
После исправления запускайте ту же команду: готовность не кешируется, поэтому
смена конфигурации или обновление файлов будут проверены заново.
`LOCAL_CHECKS_OK` означает успешность локальных проверок. Подключение
работающего туннеля к этому конфигу и доступ к Авито подтверждает агент
при первой обычной загрузке по [процедуре](VPN_HAPP.md).

## Как поставить задание

Укажите агенту:

- ссылку на задачу/исследование в Buildin;
- географию, профессию и остальные фильтры;
- способ отбора: первые N выдачи или N подходящих по явному правилу;
- лимиты просмотра и сохранения, нужные поля;
- новый каталог в `Data/avito_runs/` или checkpoint незавершённого сбора.

Пример задания — в [корневом README](../README.md#как-получить-новую-выгрузку).
Агент читает навык, запускает preflight и работает в собственной Aside-сессии.
Независимые чаты со своими сессиями и checkout не ждут друг друга; внутри
одного сбора карточки открываются последовательно. После смены города перепроверяет профессию
и остальные контролы. Перед каждой навигацией сохраняет состояние, а после
чтения карточки — исходные данные и свидетельства. Подробные действия
интерфейса и правила разбора — в [ASIDE_WORKFLOW.md](ASIDE_WORKFLOW.md).

При CAPTCHA или ограничении доступа агент сохраняет состояние и останавливается.
Продолжение начинается с checkpoint и проверки текущей страницы;
ранее сохранённые карточки не нужно открывать заново. У завершённой выгрузки
продолжения нет: следующий сбор создаёт новый каталог.

## Что передаём команде

Новые DOM-снимки и скриншоты в GitHub не загружаем. Snapshot используется для
чтения интерфейса, screenshot создаётся при необходимости диагностики локально.
Команда получает CSV, raw JSON, план/паспорт и короткое описание результата.
Исторические архивы не переписываем. Новый PR формируется по
[шаблону](templates/dataset-pr.md) через `python3 utils/dataset_pr.py`;
утилита считает новые/повторные ключи, размерность и колонки из самих CSV.
[Проверка фильтра «полный день» для Краснодара и Рязани](reports/2026-11-10-full-day-filter.md) фиксирует границы двух несобранных срезов.
[Разбор времени двух сборов](COLLECTION_TIMING.md) отделяет секунды работы
браузера от подготовки и публикации; будущие этапы замеряются отдельно.

Экспорт содержит таблицы для анализа, паспорт, план и ограничения отбора.
Исходные карточки позволяют проверить происхождение значений. Экспорт строится
из сохранённых данных: повторный запуск обработки не должен открывать сайт.
Конкретные правила обработки и её версия фиксируются вместе с результатом.

[Data/README.md](../Data/README.md) объясняет состав таблиц и версионирование,
а [ML/README.md](../ML/README.md) — как загрузить данные и закрепить их в эксперименте.
Каждый сбор отдаёт плоский CSV по [общему контракту](../Data/dataset/README.md).
Агент регистрирует проверенный экспорт, запускает `python3 utils/build_dataset.py`
и открывает PR с обновлением общей таблицы. Объединение работает офлайн для
одной или нескольких выгрузок; новые характеристики добавляют колонки.
