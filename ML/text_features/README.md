# Текстовые признаки для зарплатной модели

Исследование 17.11.2026: какие признаки из текста вакансии помогают модели
зарплатных интервалов (`ML.salary_model`), сколько в этом утечки зарплаты
и запоминания работодателя. Результаты:
[`ML/experiments/2026-11-17_text_features/`](../experiments/2026-11-17_text_features/).

## Коротко

1. На незнакомых работодателях текст полезен только как **список условий
   работы**: −4,9 % к ошибке без текста. Продовый TF-IDF на тех же
   работодателях даёт −2,4 %, около половины его выигрыша на обычной проверке
   было узнаванием работодателя.
2. Свободный текст поверх условий (даже без шаблонов, брендов и вёрстки)
   ничего не добавляет, а верхнюю границу ухудшает на 3,9 %.
3. Утечка зарплаты в тексте есть (у 5,8 % вакансий после `delete_salary`
   остаётся точная сумма), но текущая модель ею не пользуется.
4. e5-эмбеддинги хуже символьного TF-IDF, заголовок сам по себе бесполезен.

## Постановка

* Данные: `ML/data/experiments/01_location_monthly.csv` (8 906 вакансий после
  фильтров, 7 880 с нижней и 6 052 с верхней границей), как у финальной модели
  6.11.2026.
* Модель и параметры CatBoost MultiQuantile — как в `ML.salary_model --final`
  (без работодателя в признаках, калибровка по профессиям кросс-фитом).
  Меняется только текстовый блок.
* Метрика: pinball-loss по log-зарплате, среднее по P25/P50/P75 и обеим
  границам. ДИ 95 % — бутстрэп по группам (дубли или работодатели).
* Две схемы 5-fold CV:
  * **этап 1** — фолды по группам дублей, как в `ML.salary_model`; у
    работодателя из теста обычно есть другие вакансии в обучении;
  * **этап 2** — фолды по работодателю: все объявления работодателя целиком
    в тесте, модель его не видела. Это основная проверка, потому что модель
    должна оценивать вакансию по содержанию, а не по автору.

## Этап 1: фолды по дублям

| Вариант | Loss | Медианная ошибка, нижняя / верхняя | Изменение к «без текста» [95% ДИ] |
|---|---|---|---|
| Без текста (только карточка) | 0.0954 | 14.0% / 13.9% | — |
| TF-IDF только по заголовку | 0.0951 | 13.8% / 13.3% | -0.3% [-2.5; +2.9] |
| e5-эмбеддинги | 0.0925 | 12.9% / 12.9% | -3.0% [-4.6; -1.5] |
| e5 + ручные v1 | 0.0916 | 13.3% / 13.2% | -3.9% [-5.5; -2.1] |
| TF-IDF по словам | 0.0913 | 12.6% / 13.0% | -4.3% [-5.8; -2.7] |
| TF-IDF по тексту без очистки (потолок утечки) | 0.0904 | 12.5% / 13.0% | -5.2% [-6.6; -3.8] |
| TF-IDF, латиница→кириллица + delete_salary | 0.0906 | 12.7% / 12.6% | -5.0% [-6.5; -3.3] |
| Прод: TF-IDF символьный, delete_salary | 0.0905 | 12.7% / 12.6% | -5.1% [-6.6; -3.5] |
| TF-IDF, строгая очистка | 0.0906 | 12.8% / 12.8% | -4.9% [-6.5; -3.4] |
| Ручные признаки v1 (со стилем) | 0.0898 | 12.5% / 13.0% | -5.8% [-6.9; -4.7] |
| TF-IDF + ручные v1 | 0.0891 | 12.7% / 12.4% | -6.6% [-8.1; -4.9] |
| Условия работы (conditions.py) | 0.0884 | 12.4% / 12.9% | -7.3% [-8.4; -6.1] |

Прод воспроизведён до четвёртого знака (0.0902 / 0.0907 по границам).

## Этап 2: незнакомые работодатели

| Вариант | Loss | Медианная ошибка, нижняя / верхняя | Изменение к «без текста» [95% ДИ] |
|---|---|---|---|
| Без текста | 0.1049 | 16.0% / 17.1% | — |
| Прод: TF-IDF символьный | 0.1024 | 16.0% / 16.5% | -2.4% [-4.9; +0.0] |
| Условия + TF-IDF очищенного текста | 0.1016 | 15.5% / 16.9% | -3.2% [-5.3; -0.8] |
| Условия, веса 1/√объявлений работодателя | 0.1006 | 15.5% / 16.9% | -4.1% [-5.7; -2.6] |
| Условия работы | 0.0998 | 15.4% / 16.6% | -4.9% [-6.8; -2.9] |
| TF-IDF + ручные v1 (лучший этапа 1) | 0.0995 | 15.5% / 16.3% | -5.1% [-7.6; -2.5] |
| Без текста, веса 1/√объявлений работодателя | 0.1068 | 17.1% / 17.2% | +1.8% [+0.5; +3.0] |

* Условия к проду: −2,6 % [−5,3; −0,2]; с равным весом каждого работодателя
  −2,2 % [−3,2; −1,2].
* Условия + очищенный текст к условиям: +1,9 % [−0,1; +4,3], верхняя граница
  +3,9 % [+0,9; +7,5].
* Лучший вариант этапа 1 (TF-IDF + ручные v1 со «стилем») к условиям:
  −0,2 % [−2,8; +2,8] — то же качество, но со свободным текстом и стилем.
* Веса по работодателю: на метрике «каждый работодатель с равным весом»
  −0,8 % [−1,4; 0,0], на обычной +0,8 % (не значимо).
* По профессиям (условия к «без текста»): комплектовщик −12 %, грузчик
  −8 %, водитель −7 %, курьер −5 %, без профессии −2,5 %; кассир и продавец
  без значимого эффекта. К проду сильнее всего выигрывают водители (−6,8 %)
  и комплектовщики (−18 %).
* Честный уровень ошибки на незнакомых работодателях: медианная ошибка
  15–17 % против 12–13 % на обычной проверке.

## Утечка зарплаты

Доля вакансий, в тексте которых (заголовок + описание) остаётся сумма,
совпадающая с таргетом до 1 % (`leakage_audit_01_location_monthly.csv`):

| Очистка | Доля |
|---|---|
| без очистки | 30,1 % |
| `utils.delete_salary` (прод) | 5,8 % |
| латиница-двойник → кириллица + `delete_salary` | 0,7 % |
| строгая (`redaction.strict_redact`) | 0,02 % |

`delete_salary` не видит суммы в словах с латиницей-двойником («зaрплaтa
oт 110 000 pублeй»), которой обфусцированы 92 % описаний. Модель этой
утечкой не пользуется: на 515 вакансиях с утечкой прод не лучше строгой
очистки (+1,4 % [−1,4; +4,4]), TF-IDF → SVD-64 размывает конкретные числа.
Для более «цепких» представлений текста очистку нужно чинить.

## Узнаваемость работодателя

Логистическая регрессия угадывает работодателя среди 65 крупных (≥ 20
объявлений, 3 358 вакансий, частый класс 9,8 %) по:

| Признаки | Точность |
|---|---|
| только параметры карточки | 75 % |
| только условия работы | 78 % |
| карточка + условия | 80 % |
| символьный TF-IDF текста (сырого / строгого / без вёрстки) | 79–80 % |

Сети пишут одни и те же условия во всех объявлениях, поэтому полностью
скрыть крупного работодателя нельзя, и это нормально: одинаковые условия
должны давать одинаковый прогноз. Отличать нужно запоминание формулировок,
бренда и стиля — его и убирает перевод текста в закрытый список условий,
а измеряет проверка на незнакомых работодателях.

## Что внутри

| Файл | Что делает |
|---|---|
| `redaction.py` | Уровни очистки: raw / prod / homoglyph / strict / clean / content; шаблоны работодателя и бренды |
| `conditions.py` | ~100 признаков условий: оплата без сумм, график, длина смены, перки, требования, техника, транспорт, права |
| `handcrafted.py` | Ручные признаки v1 (с «стилем»: длина, эмодзи, буллеты, доля латиницы) — для сравнения |
| `embeddings.py` | multilingual-e5-base с кэшем в `ML/.cache/text_features/` |
| `run.py` | Стенд: все варианты на одинаковых фолдах; готовые варианты пропускаются |
| `analyze.py` | Попарные сравнения с бутстрэпом, метрика с равным весом работодателей |

```sh
python -X utf8 -m ML.text_features.run                 # этапы 1 и 2
python -X utf8 -m ML.text_features.run --only C2_conditions_by_employer
python -X utf8 -m ML.text_features.analyze             # paired_comparison.csv, variant_metrics.csv
```

`--backend sklearn --max-rows 2000` — быстрая проверка кода без CatBoost.

## Рекомендации

1. Основной метрикой модели сделать CV по работодателю
   (`assign_employer_cv_splits` в `run.py`).
2. Заменить текстовый блок прода (TF-IDF + SVD) на `conditions.py`
   поверх строгой очистки; свободный текст в модель не подавать.
3. Перенести нормализацию латиницы и строгую очистку в `utils/delete_salary.py`.
4. Веса по работодателю — по продуктовой задаче: чуть лучше для небольших
   работодателей, чуть хуже в среднем.

## Ограничения

* Словарь условий написан регулярными выражениями по этим же данным; полнота
  не проверялась вручную.
* Нормализация работодателя простая: «Магнит», «Магнит Доставка» и
  «Действуй сейчас. Магнит» — разные работодатели, поэтому проверка на
  незнакомых работодателях немного оптимистична для сетей.
* Шаблоны работодателя выучены на всех строках (только тексты и названия,
  без зарплат).
* Один датасет (города, месячная оплата), одно зерно; удалёнка не проверялась.
