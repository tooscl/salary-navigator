# Анализ и моделирование

Здесь команда исследует признаки вакансий, проверяет baseline и сравнивает
модели. Выбор гипотез, постановку задач и выводы ведём в Buildin; в репозитории
сохраняем код и результаты, которые коллега может воспроизвести.

## Загрузить данные

Общий CSV хранится в Git частями. Из корня репозитория восстановите его:

```sh
python3 utils/build_dataset.py --materialize
```

Команда проверяет части и перезаписывает локальный `Data/dataset/vacancies.csv`.
Готовые ячейки восстановления и загрузки, работающие также из подкаталога,
находятся в [02_load_shared_dataset.ipynb](02_load_shared_dataset.ipynb).
Затем из корня репозитория:

```python
import pandas as pd

df = pd.read_csv("Data/dataset/vacancies.csv", dtype={"id": "string"})
df.head()
```

Общая таблица пополняется проверенными сборами; параметры уже в отдельных колонках.
[Контракт и обогащение](../Data/dataset/README.md).
Установите `pandas` (`python3 -m pip install pandas`); для ноутбука нужен Jupyter.
[00_load_first_export.ipynb](00_load_first_export.ipynb) содержит готовые примеры
просмотра и фильтрации. Он использует первую выгрузку, а не общий датасет.

Архив карточек и прежний способ загрузки с проверкой паспорта сохранены
как дополнительный вариант: [01_load_with_passport.ipynb](01_load_with_passport.ipynb).
Они не нужны для обычного чтения CSV.

Исходная зарплатная строка не является готовым месячным таргетом. Неизвестные
период, налоги и нагрузку сохраняйте как неизвестные до обоснованной обработки.

## Ноутбуки, утилиты и результаты

Ноутбуки держим здесь, общие функции — в [общие utils/](../utils/).
Преобразование архивного экспорта в плоский CSV — [utils/flatten_export.py](../utils/flatten_export.py).
Прежний загрузчик с паспортом — [utils/load_dataset.py](../utils/load_dataset.py).
Очистку и признаки сохраняйте отдельно от общего CSV. Фиксируйте SHA-256
входного файла и скрипт или ноутбук с конфигурацией преобразования. Если
результат слишком велик для Git, предлагается хранить его частями с manifest
и отдельной утилитой восстановления; такой механизм для результатов экспериментов
пока не реализован.
Результат отдельного эксперимента сохраняем
в `experiments/<дата>_<короткое-имя>/`, модель — в `models/<experiment_id>/`.
Скопируйте [experiment.template.json](experiment.template.json) в каталог
эксперимента и заполните только реально выполненное. Сохраните метрики и
короткий вывод рядом. Модель сопровождается подготовкой признаков, зависимостями
и описанием входа; одного файла весов недостаточно для повторного применения.

В паспорте эксперимента фиксируем:

- путь и SHA-256 использованного CSV; паспорт и dataset_id — при работе с архивом;
- Git-коммит кода (для незакоммиченной работы — `null` и явная отметка);
- список признаков и версию преобразований;
- ID train/validation/test, правило разделения и seed;
- параметры, метрики с названием выборки и путь к модели.

Повторы ID между срезами не должны попадать в разные части проверки.
Суммы и зарплатные фразы из текста не включаем в признаки для предсказания
той же суммы. Поздний временной тест собирается отдельно; текущий набор не
подменяет проверку на новом периоде.

Работаем в личных Git-ветках, общие изменения переносим после проверки коллегой.
Новый датасет выбираем явно. Завершённые выгрузки и результаты чужих
экспериментов не перезаписываем. Актуальные датасеты перечислены в
[Data/README.md](../Data/README.md).
