# Модель зарплатного коридора M4 (нормализация v1)

Модель оценивает рыночный коридор месячной зарплаты до налога для вакансии и
показывает, где её зарплата: **ниже рынка, в рынке или выше рынка**. На
работодателях, которых модель не видела, медианная ошибка — **14,8 %**, у
медианы по «профессии × городу» — 22,3 %.

* Эксперимент: [ML/experiments/2026-11-18_normalized_v1/](../../experiments/2026-11-18_normalized_v1/),
  код: [ML/normalized_salary/](../../normalized_salary/).
* Нормализация зарплат: правила v1 из
  [Analytics/salary_normalization_v1.ipynb](../../../Analytics/salary_normalization_v1.ipynb),
  перенесены без изменений в [utils/salary_normalization.py](../../../utils/salary_normalization.py).

## Что предсказывает

Три числа на вакансию: P25, P50 и P75 месячной зарплаты до налога, в рублях.
P50 — типичная сумма для вакансии с такими условиями, P25–P75 — коридор, куда
попадает половина похожих вакансий. Зарплата вакансии ниже P25 — «ниже рынка»,
выше P75 — «выше рынка», между ними — «в рынке».

## Таргет: нормализация зарплат v1

Из `salary_raw` правила v1 получают одну месячную сумму до налога
(`salary_month_gross_normalized`):

* «от X» → X; вилка → середина; «до Y» → вакансия не используется;
* «на руки» → «до налога» по прогрессивной шкале НДФЛ;
* оплата за смену, день, час, неделю → ставка в час × 176 часов в месяц; для
  смены нужны «Количество рабочих часов в день», при нескольких вариантах
  длительности на каждый вариант своя строка;
* сумма без периода считается месячной (допущение v1).

1 / число вариантов, поэтому каждая вакансия учитывается один раз.

## Признаки

Название работодателя и суммы из текста в модель не попадают.

1. **Параметры карточки Авито** (37): город, регион, профессия, график,
   занятость, способ оформления, часы в день, частота выплат, сфера компании,
   опыт, «в том числе для кандидатов», медкнижка, дни в неделю, категория прав,
   способ и вид доставки и другие.
2. **Формат оплаты** (4): единица (смена, час, неделя, без периода), вид суммы
   («от», вилка, точная), «на руки» или до налога, длительность смены.
3. **Условия работы из текста** (103, `ML/text_features/conditions.py`):
   проживание, питание, развозка, ежедневные и еженедельные выплаты, ночные
   смены, графики 2/2 и 5/2, категория C/E, погрузчик, ТСД, длина смены и др.
   Извлекаются из описания после строгой очистки от сумм.

Самые важные признаки (по кросс-валидации): профессия (10 %), регион (10 %), длительность смены (9 %),
сфера компании (7 %), «в том числе для кандидатов» (5 %). Условия из текста
в сумме — 22 %.

## Модель

CatBoost, функция потерь MultiQuantile (P25, P50, P75 логарифма зарплаты в одной
модели), глубина 8, скорость обучения 0,05, l2 5, ≈1 083 дерева — среднее
лучших итераций по фолдам. Интервал откалиброван сдвигом квантилей (среднее
сдвигов по фолдам), чтобы в P25–P75 попадала половина вакансий.

## Метрики

Проверка — 5 фолдов, сгруппированных по работодателю: каждую вакансию
предсказывает модель, которая не видела ни одного объявления её работодателя.
Финальная модель обучена на всех строках, поэтому её качество — это оценка
по кросс-валидации.

| Метрика | M4 | Медиана «профессия × город» |
|---|---|---|
| Медианная ошибка, % | **14,8 %** | 22,3 % |
| Медианная ошибка, ₽ | 13 800 ₽ | 21 000 ₽ |
| Средняя ошибка (MAE) | 26 700 ₽ | 37 700 ₽ |
| Средняя ошибка, % (MAPE) | 23,0 % | 33,8 % |
| Прогноз в пределах ±10 % | 37 % вакансий | 24 % |
| Прогноз в пределах ±20 % | 62 % вакансий | 45 % |
| Попадание в P25–P75 (цель 50 %) | 51 % | 53 % |
| Медианная ширина P25–P75 | 32 % от P50 | 51 % от P50 |
| Pinball-loss (log) | 0.0951 | 0.1352 |
| Pinball-loss, работодатели с равным весом | 0.1108 | 0.1515 |

Pinball-loss M4 ниже медианы сегмента на 29,7 % [−31,4; −27,9] (95 % ДИ,
бутстрэп по работодателям).

**Сравнение с другими моделями эксперимента** (pinball-loss, медианная ошибка):

| Модель | Loss | Медианная ошибка |
|---|---|---|
| M0 медиана «профессия × город» | 0.1352 | 22,3 % |
| M1 линейная (карточка + формат + условия) | 0.1117 | 18,8 % |
| M5 CatBoost без формата оплаты | 0.1037 | 16,5 % |
| M3 CatBoost без условий из текста | 0.1006 | 15,5 % |
| M2 sklearn-бустинг (те же признаки, что у M4) | 0.0964 | 14,9 % |
| **M4** | **0.0951** | **14,8 %** |

Условия из текста улучшают модель на 5,5 % [−6,6; −4,3] (M4 к M3), формат
оплаты — на 8 % (без него loss +9,1 % [+7,5; +10,8]). M2 почти не уступает
(M4 лучше на 1,4 % [−2,7; −0,1]) и обучается в 5 раз быстрее.

## Как пользоваться

```python
import pandas as pd
from ML.normalized_salary.predict import load_model, predict_corridor

model = load_model()   # ML/models/2026-11-18_normalized_v1_M4
vacancies = pd.read_csv("Data/dataset/vacancies.csv", dtype=str).head(100)
result = predict_corridor(model, vacancies)
result[["title", "salary_raw", "salary_month_gross_normalized", "p25", "p50", "p75", "verdict"]]
```

На вход — строки в схеме общего датасета. Зарплата сначала нормализуется
правилами v1: формат оплаты — вход модели, нормализованная сумма сравнивается
с коридором. Нужен `catboost` (как в `ML/salary_model/requirements.txt`).

## Ограничения

* Вакансии без зарплаты, только с «до Y», сменные без часов и сдельные модель
  не оценивает: для них правила v1 не дают суммы и формата оплаты.
* 75 % вакансий — сумма без периода, принятая за месячную по допущению v1;
  40 % — «от X», взятое как точная сумма. [Контракт для ML](../../../Analytics/salary_segment_results/ml_salary_contract.json)
  так делать не рекомендует; проверить допущения на этих данных нельзя.
* Модель учится и проверяется на одной нормализации: ошибка показывает,
  насколько предсказуемы нормализованные суммы, а не насколько верна нормализация.
* Часть пользы от формата оплаты — модель заново выучивает формулу пересчёта
  смены через часы.
* Охват — города, без вахты и удалёнки; хвост профессий (охранник, кладовщик,
  упаковщик) — единицы и десятки вакансий, качество там не оценено.
* Вакансии из обучающей выборки модель видела: для них вердикт оптимистичен.
