# Модели на нормализации зарплат v1

Эксперимент 18.11.2026: таргет — `salary_month_gross_normalized` по правилам
[Analytics/salary_normalization_v1.ipynb](../../Analytics/salary_normalization_v1.ipynb)
(месячная сумма до налога). Код правил перенесён без изменений в
[utils/salary_normalization.py](../../utils/salary_normalization.py): на текущем
датасете результат совпадает с ноутбуком полностью. Результаты —
[ML/experiments/2026-11-18_normalized_v1/](../experiments/2026-11-18_normalized_v1/).

## Коротко

* Лучшая модель — CatBoost на параметрах карточки, формате оплаты и условиях
  работы из текста (M4): медианная ошибка 14,8 % на незнакомых работодателях,
  на 29,7 % меньше pinball-loss, чем у медианы сегмента «профессия × город».
* Бустинг из sklearn (M2) почти так же хорош (−1,4 % [−2,7; −0,1] в пользу
  CatBoost) и обучается в 5 раз быстрее.
* Условия работы из текста дают −5,5 % [−6,6; −4,3] (M4 к M3).
* Формат оплаты (единица, вид суммы, налог, вариант длительности смены) даёт
  −8 %: без него ошибка растёт на 9,1 % [+7,5; +10,8], на сменных вакансиях —
  на 26 %. Значительная часть этого — модель заново выучивает формулу
  пересчёта смены через часы.

## Данные

* Вход: `Data/dataset/vacancies.csv` (32 097 вакансий, SHA-256 в `experiment.json`).
* Охват по замыслу ноутбука: без вахты, без удалёнки, без военных вакансий —
  20 391 вакансия. Фильтр в ноутбуке сравнивает с «Удаленно» через «е», в данных
  «Удалённо» через «ё», поэтому там удалёнка не исключается.
* Нормализовано 15 932 вакансии (22 732 строки: у 2 098 сменных вакансий
  несколько вариантов длительности смены, на каждый — своя строка; строка
  весит 1 / число вариантов).
* В модель идут суммы 10 000 – 1 000 000 ₽ в месяц: 15 408 вакансий,
  22 194 строки. Ниже — в основном суммы за смену без указанного периода,
  которые правило считает месячными; выше — смены, делённые на короткую длительность.
* Компактная таблица таргетов: `ML/data/experiments/05_normalized_v1.csv`.

## Проверка

5 фолдов, сгруппированных по работодателю (все его объявления — в тесте),
стратификация «профессия × город». Все модели предсказывают P25/P50/P75 логарифма
месячной суммы; калибровка одна для всех — сдвиг квантилей по валидации фолда.
Метрики взвешены так, что каждая вакансия считается один раз. ДИ 95 % — бутстрэп
по работодателям.

Медианная ошибка M4 по профессиям: кассир 8,6 %, грузчик 12,6 %, продавец

(принята за месяц) 15,1 %, час 31 % (118 вакансий), неделя 41 % (45 вакансий).

Время на ноутбуке (16 потоков): M0–M1 — секунды, M2 — 3 мин, каждая модель
CatBoost — 14–15 мин.

## Ограничения

* 75 % вакансий — сумма без периода, принятая за месяц по допущению v1;
  [контракт для ML](../../Analytics/salary_segment_results/ml_salary_contract.json)
  так делать не рекомендует. Проверить допущение на этих данных нельзя.
* «от X» — 40 % вакансий — берётся как точная сумма X (по контракту это не точка).
* Пересчёт смены: ставка в час × 176 ч; это сценарный эквивалент, не фактический доход.
* Модель учится и проверяется на одной и той же нормализации, поэтому ошибка
  показывает, насколько предсказуемы нормализованные суммы, а не насколько верна
  сама нормализация.
* Таргет отличается от `ML.salary_model` (там нижняя и верхняя границы без
  пересчёта налога), напрямую цифры не сравниваются.

## Запуск

```sh
python -X utf8 -m ML.normalized_salary.run                 # все модели, ~50 мин
python -X utf8 -m ML.normalized_salary.run --skip-catboost  # M0-M2, ~4 мин
python -X utf8 -m ML.normalized_salary.run --fast           # облегчённый CatBoost, отдельная папка
python -X utf8 -m unittest utils.test_salary_normalization
```
